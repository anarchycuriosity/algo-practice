# 002. 根据 `src/` 推测能力与思考风格

## 观察范围

本次观察对象为 `src/` 下已有源码和少量笔记。仓库内目前约有 50 个 `.cpp` 文件和 4 个 `.md` 文件，覆盖 BFS、二分、背包 DP、图论、堆、数学、贪心、字符串、比赛临时代码等。

重点阅读的代表文件包括：

- `src/bfs/01_填充染色.cpp`
- `src/binary/01_二分法解一元三次方程(实数解).cpp`
- `src/dp/08_双背包匹配.cpp`
- `src/heap/01_堆模板(P3378).cpp`
- `src/graph/02_有向图到达最远序号(图的遍历简单版）.cpp`
- `src/CF/round1111/C和为奇数的子序列翻转.cpp`
- `src/races/AHCPC26/A_记忆哈希表+递归.cpp`
- `src/math/07_非严格弱序不要用比较器_更复杂的邻项.cpp`

## 能力推测

### 1. 不是纯复制型，具备机制追问意识

很多代码不是简单提交版，而是带有大量“为什么”的注释。例如：

- 堆模板中解释了结构底线和值底线，以及 `push`、`pop` 如何局部修复。
- 图遍历题中解释了为什么反向建图能让大编号点先染色小编号点。
- BFS 填色题中记录了从四个角出发不够，必须从整条边界出发。
- 背包题中解释了为什么装满型初始化要用负无穷。

这说明用户学习时不是只机械抄代码，而是在尝试补底层动机。这个优势要保留。

### 2. 已经接触过“对立转化”

代码中多次出现逆向思考：

- `src/bfs/01_填充染色.cpp`：不直接找圈内 0，而是从边界 0 出发标记圈外。
- `src/graph/02_有向图到达最远序号(图的遍历简单版）.cpp`：不正向从每个点找最大可达点，而是反向建图，从大编号向小编号染色。
- `src/greedy/02_从n变化到m.cpp`：从目标反推，减少无意义搜索。
- `src/races/AHCPC26/A_记忆哈希表+递归.cpp`：围绕数字折半与记忆化状态减少重复计算。

这类思维是网络赛中非常关键的能力雏形。后续训练应主动追问：“能不能反着想？”

### 3. 复盘意识强，但比赛动作偏慢

源码中大量保留错误原因：

- “不仅仅是四个端点入队，而是四个边。”
- “有上界判定但缺少下界。”
- “初始化这里考场上记错了。”
- “比较错了，这会漏掉当前层的节点。”
- “输入错了，曾经写成 v1。”
- “第二次提交错误，虽然 count 是对的，但是不一定最小。”

这说明用户能识别错误并愿意记录，但也说明比赛中容易在基本工程细节上失分。后续训练不能只练算法模型，还要练提交前检查清单。

### 4. 抽象解释偏长，需要压缩成判定信号

用户擅长用自然语言展开理解，例如堆、贪心、记忆化递归的说明都很长。这对学习期是好事，但比赛中必须压缩。

训练目标不是删掉这种思考，而是把长解释压缩成：

- 这题是什么模型？
- 为什么这个模型能用？
- 哪个变量是状态？
- 哪个边界最危险？
- 复杂度是否过得去？

每题 AC 后必须写一句“下次识别信号”，否则知识无法迁移。

## 主要风险清单

1. 边界漏判：BFS/DFS 坐标上下界、二分左右边界、区间 DP 的 `k < j`。
2. 初始化不稳：DP 有效起点、负无穷哨兵、距离数组、访问数组。
3. 状态合法性不稳：无效状态可能参与答案合并。
4. 模板与变体混合：改造模板时容易留下旧方案残骸。
5. 代码风格不统一：仍有 `using namespace std;`、`#include <bits/stdc++.h>`、宏别名和临时文件。
6. 贪心证明薄：能感到“这样做更少”，但需要用交换论证、反证或构造证明稳住。
7. 临场拼写和输入变量错误：说明写完代码后的静态检查还不够固定。

## 后续魔鬼训练要求

### 做题前

必须先写：

```text
数据范围：
暴力复杂度：
可能模型：
核心不变式：
```

### 写代码前

必须确认：

```text
数组大小：
下标范围：
初始化值：
非法状态：
答案位置：
```

### AC 后

必须复盘：

```text
耗时：
是否独立 AC：
第一次卡点：
最危险边界：
下次识别信号：
```

## 教练策略

之后辅助用户时，不能只给标准题解。应优先逼用户做三件事：

1. 从题面数据范围推出复杂度。
2. 从操作目标推出模型，而不是从记忆中硬套模板。
3. 用反例和不变式检验当前方案。

若用户请求完整代码，仍然可以给，但必须先完成非源码层面的分析，并且源码放在最后。
